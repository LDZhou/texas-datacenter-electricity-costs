# Texas data center electricity costs

Experiments supporting the original paper on data center demand, infrastructure
expansion, wholesale prices, and residential electricity costs in ERCOT.
The study considers 2019–2023 weather, May–October at three-hour resolution,
and an announced 2030 scenario of 371 projects totaling approximately 38.9 GW.

This package preserves the original technology scope: new OCGT, solar, onshore
wind, four-hour batteries and transmission, subject to the selected mode.
Existing CCGT remains dispatchable; **new CCGT is not a candidate**.
Seasonal runs retain full annualized capital costs. Later CCGT and other
scientific sensitivity experiments are outside this repository.

## Layout

- `workflow/`, `config/`, `pyproject.toml`, `uv.lock`: retained PyPSA-USA workflow
  and dependencies; upstream attribution is in `PROVENANCE.md` and `LICENSE.md`.
- `configs/config_vopt.yaml`: original seasonal baseline configuration.
- `scripts/`: data-center experiments, analysis, plotting, and smoke test.
- `slurm/`: portable baseline, experiment, and smoke launchers.
- `powerworld/`: interface and reserved collaborator contribution.
- `private/`, `results/`, `data/`, `cutouts/`, `resources/`: local, ignored inputs/outputs.

## Environment and private configuration

Use Python 3.11 and the supplied dependency lock (PyPSA 0.30.2, Gurobi 13.0.1).
With uv installed, run `uv sync --frozen --no-install-project`, then activate
`.venv/bin/activate`. The project itself is run as scripts, not installed as a package.
A valid Gurobi installation/license is required. Set `GRB_LICENSE_FILE` to
your own license path in your shell; no license belongs in the repository.

For upstream data acquisition, copy `config/config.api.example.yaml` to
`config/config.api.yaml` and enter **your own** EIA API key locally.
The real file is ignored. Never put keys in command-line arguments, shared logs,
README files or commits. No credential from the author's environment is supplied.

Run all commands from the repository root. Create the upstream data alias once:
`ln -s workflow/repo_data repo_data`. Create `logs/` before using sbatch.

## Data

The experiment entry point accepts prepared networks at
`results/starting_networks/start_2019.nc` through `start_2023.nc`.
These large historical artifacts are not distributed in Git. An archival data
release is still required for reproducing the published realization exactly.

Alternatively rebuild with the upstream workflow. Its retrieval rules specify
the external Zenodo/NREL bundles; weather cutouts and other upstream inputs
must be available for all five years. `build_cutout` is disabled in the original
configuration. Baseline jobs share intermediate resources and must run serially.
The source-data rebuild is distinct from the synthetic integration test below.

The announced-project spreadsheet is private until redistribution permission is
established. Supply it with `--dc-data /absolute/path/TX_datacenters.xlsx`.
Expected columns: `full_address`, `State`, `current_mw`, `construction_mw`,
`planned_mw` (capacities in MW). City matching and ERCOT filtering are performed
by `dc_common.py`. A synthetic spreadsheet is generated by the smoke test.
Historical price validation additionally needs `private/validation_2021.nc`
and the historical price data described in `validate_2021_full_year_network.py`.

## Run

Activate the environment before submitting; replace ACCOUNT and PARTITION with
your cluster's values. GPU requirements depend on the partition, not the model.
The original twelve numbered Slurm scripts are replaced by one matrix launcher.

```bash
mkdir -p logs
sbatch --account=ACCOUNT --partition=PARTITION --array=0-4%1 slurm/base.sbatch
# After all starting networks exist:
sbatch --account=ACCOUNT --partition=PARTITION --array=0-4%2 slurm/experiment.sbatch baseline
sbatch --account=ACCOUNT --partition=PARTITION --array=0-4%2 slurm/experiment.sbatch all2030 --mode full_tx --dc-data /absolute/path/TX_datacenters.xlsx
sbatch --account=ACCOUNT --partition=PARTITION --array=0-119%2 slurm/experiment.sbatch multiloc --mode full_tx
```

Repeat the last two commands for `dispatch`, `generation`, `generation_storage`,
`generation_tx`, `transmission`, and `full_tx`. All2030 index 0–4 maps to
2019–2023. Multiloc index enumerates year, location (Houston, Austin, Tolar,
DFW South, Abilene, Childress), then scale (500, 1000, 3000, 5000 MW).
Limit total simultaneous jobs across arrays to your license allowance.
For one direct run: `python scripts/run_paper.py all2030 --mode full_tx --index 4 --dc-data /absolute/path/TX_datacenters.xlsx`.

After the required runs finish:

```bash
python scripts/run_paper.py analysis
python scripts/run_paper.py rep
python scripts/plot_paper.py --skip-validation
```

REP uses the original paper's $5,000/MWh price cap and matched N-1 transmission
adder, replacing stale $0.8572/MWh launch parameters. Its engineering adder is
an explicit historical input; see `powerworld/README.md`.

Figures are written to `results/nc_paper_figures/`. The framework figure has
five panels (map, peak-load overlay, investment, cap hours, residential increment).
`--skip-validation` skips only the separate historical-price validation input;
it does not skip the experiment/REP figures. Supply the external validation
network and historical price files before omitting that flag.

## Minimal integration test

```bash
python scripts/smoke_test.py
# Or, from the activated environment:
sbatch --account=ACCOUNT --partition=PARTITION slurm/smoke.sbatch
```

The test generates a small synthetic network and project table, prepares a
frozen starting network, solves a baseline plus both scenario families in all
six modes (14 solves including the synthetic input solve), verifies that CCGT expansion stays disabled, checks
metrics and price decomposition, runs a small REP simulation and saves a plot.
Inspect `results/smoke/verification.json`. Synthetic results are not paper results.
This test does not validate upstream downloads, the full-size optimization,
or the collaborator's PowerWorld workflow.

## Reproducibility notes

Legacy full-state load profiles used Python's process-dependent `hash()`.
This package uses SHA-256 seeds and a local legacy-compatible NumPy RandomState.
New runs are deterministic at the profile level, but can differ from historical
profiles whose seeds were not archived. Exact historical numerical replication
requires the original solved networks/load profiles and software environment.
Solver non-optimal status or a non-finite objective stops output generation.
No new residual rejection gate or CCGT model changes have been introduced.

See `PROVENANCE.md` for scope, known limitations and the cleanup record.
